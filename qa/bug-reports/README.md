# qa/bug-reports/ — bug reports

## Purpose
One Markdown file per confirmed bug, written from the template in [docs/roles/QA_GUIDE.md](../../docs/roles/QA_GUIDE.md). GitHub Issues can mirror these later; the repo copy is the durable record (rule 9).

## Contents
Currently empty — no bugs filed.

## Filename
`YYYY-MM-DD_short-title.md` — e.g. `2026-11-11_manifest_schema_typo.md`.

## Lifecycle
`open → in-progress → fixed (link the fixing PR) → verified`. Update status by editing the report **in the PR that changes it**; a failing check is retested, not deleted (rule 8).

## Contributing
Before filing: reproduce it, confirm it's not already filed here, and fill every template field honestly ("cannot reproduce consistently" is a valid field value).

## Dependencies
None.
